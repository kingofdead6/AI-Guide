From waveform to features

Audio is sampled (16 kHz is standard for speech). The short-time Fourier transform slices it into overlapping windows (~25 ms, hop ~10 ms) and measures the energy at each frequency. Human hearing is roughly logarithmic in pitch, so frequencies are mapped to the mel scale \(m=2595\log_{10}(1+f/700)\) and energies are log-compressed: the log-mel spectrogram is the standard input. (MFCCs, a further cosine transform, were standard before deep learning.)

Speech recognition (ASR)

  • CTC loss solves the alignment problem: many audio frames map to few characters, and we don't know which frame is which letter. The model outputs a distribution per frame over characters plus a special blank; any frame-level path that collapses to the target (merge repeats, drop blanks: "hh-e-ll-ll-oo" → "hello") counts, and CTC sums the probability of all such paths with dynamic programming.
  • Encoder–decoder models (e.g. Whisper) treat ASR like translation: an audio encoder and a text decoder with cross-attention, trained on large weakly labelled multilingual data.
  • Word error rate: \(\text{WER}=\frac{S+D+I}{N}\) (substitutions, deletions, insertions over reference words), computed with edit distance ([[dsa]]).

Speech generation and beyond

Text-to-speech: text → acoustic model → mel spectrogram → vocoder → waveform, or end-to-end models over discrete audio tokens from a neural codec. Other tasks: speaker diarization ("who spoke when"), voice activity detection, keyword spotting, emotion recognition. Speech-native LLMs process audio tokens directly for low-latency voice conversation.

import torch, torchaudio
wave, sr = torchaudio.load("speech.wav")                       # (channels, samples)
wave = torchaudio.functional.resample(wave, sr, 16000)
mel = torchaudio.transforms.MelSpectrogram(sample_rate=16000, n_fft=400, hop_length=160, n_mels=80)(wave)
log_mel = torch.log(mel + 1e-6)                                # (1, 80, frames): model input
