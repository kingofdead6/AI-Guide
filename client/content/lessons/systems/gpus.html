The machine

A GPU has many streaming multiprocessors (SMs), each running thousands of threads, with tensor cores that perform small matrix multiply-accumulates in low precision very fast. Thousands of threads hide memory latency by switching between work. The programming model: launch a kernel over a grid of blocks; each block's threads share fast on-chip memory.

Compute-bound or memory-bound?

Arithmetic intensity = FLOPs performed per byte moved from memory. Compare it to the hardware's ratio of peak FLOP/s to memory bandwidth (the "ridge point", often a few hundred FLOPs/byte for bf16 on modern data-centre GPUs):

$$\text{matmul }(m\times k)(k\times n):\ \ \frac{2mkn\ \text{FLOPs}}{2(mk+kn+mn)\ \text{bytes (bf16)}}\qquad\text{vs.}\qquad \text{elementwise add: }\frac{1\ \text{FLOP}}{6\ \text{bytes}}$$
  • Large matmuls are compute-bound: good. Elementwise ops, normalization, softmax and small-batch LLM decoding are memory-bound: the GPU waits for data.
  • Kernel fusion combines several memory-bound ops into one kernel so data is read once (what torch.compile and FlashAttention do).
  • Batching raises intensity: a decode step for 64 sequences reads the weights once for all of them.
  • MFU (model FLOPs utilization) = achieved useful FLOP/s ÷ peak. Good large-scale training runs reach roughly 40–60%.

Writing a kernel: Triton

import torch, triton, triton.language as tl

@triton.jit
def add_kernel(x_ptr, y_ptr, out_ptr, n, BLOCK: tl.constexpr):
    pid = tl.program_id(0)                       # which block am I?
    offs = pid * BLOCK + tl.arange(0, BLOCK)
    mask = offs < n                              # guard the tail
    x = tl.load(x_ptr + offs, mask=mask); y = tl.load(y_ptr + offs, mask=mask)
    tl.store(out_ptr + offs, x + y, mask=mask)

def add(x, y):
    out = torch.empty_like(x); n = x.numel()
    add_kernel[(triton.cdiv(n, 1024),)](x, y, out, n, BLOCK=1024)
    return out

# Usually you don't need custom kernels: try torch.compile(model) and fused library ops first,
# then profile with torch.profiler to find the real bottleneck.
Practice problem
  1. Batch-1 decoding of a 7B model in bf16 on a GPU with ~3 TB/s of memory bandwidth: what is the best-case tokens per second?
    Solution
    Each token must read all 14 GB of weights: 3,000 GB/s ÷ 14 GB ≈ 210 tokens/s at most (less in practice, plus KV-cache reads). That's why decode speed is limited by memory bandwidth, and why quantization (fewer bytes) and batching (more tokens per weight read) help so much.
