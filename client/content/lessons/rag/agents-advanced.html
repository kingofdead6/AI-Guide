Tools and the Model Context Protocol

Tools are the agent's interface to the world, so design them like a good API for a new colleague: clear names, precise descriptions, few required arguments, informative errors, and outputs that are concise but complete. The Model Context Protocol (MCP) is an open standard where servers expose tools, resources and prompts, and clients (assistants, IDEs, agent frameworks) connect to them, so one integration works across many AI applications.

# A minimal MCP server with the official Python SDK (check the SDK docs for the current API)
from mcp.server.fastmcp import FastMCP
mcp = FastMCP("orders")

@mcp.tool()
def order_status(order_id: str) -> dict:
    """Look up the shipping status of an order by its ID (format: ORD-12345)."""
    return db_lookup(order_id)          # your code; return structured, concise data

if __name__ == "__main__":
    mcp.run()

Memory and planning

Working memory is the context window: summarize or drop old turns as it fills. Long-term memory is an external store the agent can write facts to and search later (often a RAG index). Planning ranges from implicit (ReAct: think, act, observe) to explicit plans that are revised after each step, plus reflection (critique the last attempt before retrying).

Reliability and safety checklist

  • Step, time and cost budgets; stop and report when exceeded.
  • Validate every tool call's arguments against its schema; retry with the error message on failure.
  • Make actions idempotent or reversible; require human approval for irreversible ones (payments, emails, deletions).
  • Sandbox code execution and browsing; give each tool the least privilege it needs.
  • Treat tool outputs, retrieved documents and web pages as untrusted data: they can contain prompt injections.
  • Log full trajectories; evaluate on end-to-end task success, not single responses. Multi-agent setups multiply cost and failure modes, so add agents only when a single agent with good tools clearly fails.
