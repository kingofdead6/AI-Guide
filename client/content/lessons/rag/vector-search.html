Embedding models

An encoder maps text (or images) to \(\mathbf e\in\mathbb R^d\) (typically 384–3072 dimensions) so that similar meaning gives high cosine similarity. They are trained contrastively with the InfoNCE loss ([[vit-clip]]): a query and its relevant passage are positives, other passages in the batch (and mined "hard negatives") are negatives. Normalize embeddings to unit length so that dot product = cosine similarity.

Exact vs approximate search

Brute-force search over \(N\) vectors costs \(O(Nd)\) per query. Fine for up to roughly a million vectors with good hardware, too slow beyond. Approximate nearest neighbour (ANN) indexes trade a little recall for big speedups:

IndexIdeaTrade-offs
IVFk-means the vectors into clusters; search only the nprobe closest clustersFast; recall depends on nprobe
PQ (product quantization)Split vectors into \(m\) sub-vectors and replace each with the ID of its nearest centroid in a small codebookHuge memory savings; approximate distances
HNSWMulti-layer proximity graph; greedy search from a sparse top layer down to dense lower layersExcellent recall/latency; more memory; the common default

Vector stores: FAISS (library), pgvector (Postgres extension), and dedicated databases such as Qdrant, Weaviate, Milvus and Chroma. Choose based on scale, filtering needs, and what you already run.

from sentence_transformers import SentenceTransformer
import faiss
enc = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")      # small English model
docs = ["The cat sat on the mat.", "Stocks fell sharply today.", "Kittens love to nap."]
E = enc.encode(docs, normalize_embeddings=True).astype("float32")         # (3, 384)

index = faiss.IndexFlatIP(E.shape[1])          # exact inner-product search
index.add(E)
q = enc.encode(["sleepy cats"], normalize_embeddings=True).astype("float32")
scores, ids = index.search(q, k=2)
print([docs[i] for i in ids[0]], scores)

# HNSW for scale:  index = faiss.IndexHNSWFlat(d, 32, faiss.METRIC_INNER_PRODUCT)

For Arabic or mixed-language data, use a multilingual embedding model and test it on your own queries; quality varies a lot across languages.
