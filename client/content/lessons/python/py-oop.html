Classes bundle state and behaviour

A class defines a new type: the data each object holds (attributes) and what it can do (methods). In ML code you meet classes constantly: nn.Module, Dataset, tokenizers, API clients, config objects.

class RunningMean:
    """Tracks the mean of a stream of numbers without storing them."""

    def __init__(self):
        self.n = 0
        self.mean = 0.0

    def update(self, x: float) -> None:
        self.n += 1
        self.mean += (x - self.mean) / self.n     # incremental mean

    def __repr__(self) -> str:                   # what print() shows
        return f"RunningMean(n={self.n}, mean={self.mean:.4f})"

loss_meter = RunningMean()
for loss in [0.9, 0.7, 0.5]:
    loss_meter.update(loss)
print(loss_meter)        # RunningMean(n=3, mean=0.7000)

self is the object the method is called on: loss_meter.update(0.9) is RunningMean.update(loss_meter, 0.9).

Inheritance and composition

class Tokenizer:
    def tokenize(self, text: str) -> list[str]:
        raise NotImplementedError

    def __call__(self, text: str) -> list[str]:   # lets you write tok("...")
        return self.tokenize(text)

class WhitespaceTokenizer(Tokenizer):
    def tokenize(self, text):
        return text.split()

class LowercaseTokenizer(WhitespaceTokenizer):
    def tokenize(self, text):
        return super().tokenize(text.lower())     # reuse the parent's logic

tok = LowercaseTokenizer()
print(tok("The Cat SAT"))    # ['the', 'cat', 'sat']

Prefer composition (an object that holds other objects) over deep inheritance trees. A PyTorch model is composition: a Transformer holds a list of Blocks, each holding attention and MLP modules.

Dataclasses: classes for data

Most "classes" in ML projects are records: configs, examples, results. @dataclass writes __init__, __repr__ and __eq__ for you.

from dataclasses import dataclass, field, asdict

@dataclass
class TrainConfig:
    model: str = "small"
    lr: float = 3e-4
    batch_size: int = 32
    epochs: int = 10
    tags: list[str] = field(default_factory=list)   # mutable default done right

    def steps_per_epoch(self, n_examples: int) -> int:
        return -(-n_examples // self.batch_size)    # ceiling division

cfg = TrainConfig(lr=1e-3, tags=["baseline"])
print(cfg)                   # TrainConfig(model='small', lr=0.001, ...)
print(asdict(cfg))           # plain dict, ready for JSON or experiment tracking

@dataclass(frozen=True)      # immutable and hashable
class Example:
    text: str
    label: int

The data model: dunder methods

Python's built-in syntax calls special "dunder" (double underscore) methods. Implement them and your objects work with len(), indexing, for loops, + and more. This is exactly how a PyTorch Dataset plugs into a DataLoader.

SyntaxCalls

x(…)x.__call__(…) (how model(inputs) works)

class TextDataset:
    def __init__(self, texts, labels):
        assert len(texts) == len(labels)
        self.texts, self.labels = texts, labels

    def __len__(self):
        return len(self.texts)

    def __getitem__(self, i):
        return {"text": self.texts[i], "label": self.labels[i]}

ds = TextDataset(["good", "bad", "great"], [1, 0, 1])
print(len(ds), ds[1])          # 3 {'text': 'bad', 'label': 0}
for ex in ds:                  # works because __getitem__ raises IndexError at the end
    print(ex["text"])

class Vec2:
    def __init__(self, x, y): self.x, self.y = x, y
    def __add__(self, o): return Vec2(self.x + o.x, self.y + o.y)
    def __matmul__(self, o): return self.x * o.x + self.y * o.y     # dot product with @
    def __repr__(self): return f"Vec2({self.x}, {self.y})"

print(Vec2(1, 2) + Vec2(3, 4), Vec2(1, 2) @ Vec2(3, 4))   # Vec2(4, 6) 11

Class attributes, class methods and static methods

class Model:
    registry = {}                      # class attribute: shared by all instances

    def __init__(self, name):
        self.name = name

    @classmethod
    def from_config(cls, cfg: dict):   # alternative constructor, like from_pretrained
        return cls(cfg["name"])

    @staticmethod
    def param_count(d_in, d_out):      # plain function grouped with the class
        return d_in * d_out + d_out

m = Model.from_config({"name": "tiny"})
print(m.name, Model.param_count(784, 10))   # tiny 7850
Where you will see thisAutoModel.from_pretrained(...) is a class method; model(x) calls __call__, which runs hooks then your forward; DataLoader needs only __len__ and __getitem__ from your dataset.
Practice problem
  1. Write a dataclass Metrics with fields tp, fp, fn and properties precision, recall and f1 that handle division by zero.
    Solution
    @dataclass
class Metrics:
    tp: int = 0
    fp: int = 0
    fn: int = 0
    @property
    def precision(self): return self.tp / (self.tp + self.fp) if self.tp + self.fp else 0.0
    @property
    def recall(self): return self.tp / (self.tp + self.fn) if self.tp + self.fn else 0.0
    @property
    def f1(self):
        p, r = self.precision, self.recall
        return 2 * p * r / (p + r) if p + r else 0.0
