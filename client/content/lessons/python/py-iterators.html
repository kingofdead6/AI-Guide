Iterables and iterators

A for loop works on anything iterable. Under the hood it calls iter(x) to get an iterator, then calls next() on it until StopIteration. An iterator produces values one at a time and remembers where it is; it can only be consumed once.

it = iter([10, 20, 30])
next(it), next(it), next(it)     # 10, 20, 30
# next(it) now raises StopIteration

squares = map(lambda v: v * v, range(5))   # lazy: nothing computed yet
print(list(squares))                       # [0, 1, 4, 9, 16]
print(list(squares))                       # []  (already consumed)

Generators: lazy sequences

A function containing yield becomes a generator. Each yield hands one value to the caller and pauses until the next value is requested. Generators let you stream data that would never fit in memory: a 500 GB text corpus, a stream of LLM tokens, an endless data loader.

def read_jsonl(path):
    """Yield one record at a time from a JSON-lines file of any size."""
    import json
    with open(path, encoding="utf-8") as f:
        for line in f:
            if line.strip():
                yield json.loads(line)

def batched(iterable, n):
    """Group any iterable into lists of size n (the last may be shorter)."""
    batch = []
    for item in iterable:
        batch.append(item)
        if len(batch) == n:
            yield batch
            batch = []
    if batch:
        yield batch

for batch in batched(range(7), 3):
    print(batch)            # [0, 1, 2]  [3, 4, 5]  [6]

total = sum(x * x for x in range(1_000_000))   # generator expression: no list in memory

Pipelines of generators process data in constant memory: batched(clean(read_jsonl(path)), 32) reads, cleans and batches one record at a time.

Where you will see thisPyTorch IterableDataset, Hugging Face streaming datasets, and streaming LLM APIs (a generator of text chunks) all follow this pattern. yield from other_gen() delegates to another generator.

itertools and functools

import itertools as it
list(it.islice(it.count(), 5))                 # [0, 1, 2, 3, 4]: first 5 of an infinite counter
list(it.chain([1, 2], [3]))                    # [1, 2, 3]
list(it.product(["lr=1e-3", "lr=1e-4"], [16, 32]))   # grid search combinations
for key, group in it.groupby(sorted(["ab", "ac", "b"]), key=lambda s: s[0]):
    print(key, list(group))                    # a ['ab', 'ac']  b ['b']

from functools import lru_cache, partial, reduce
@lru_cache(maxsize=None)                       # memoize: compute each n once
def fib(n): return n if n < 2 else fib(n - 1) + fib(n - 2)
print(fib(80))

def scale(x, factor): return x * factor
double = partial(scale, factor=2)              # pre-fill an argument
print(double(21), reduce(lambda a, b: a * b, [1, 2, 3, 4]))   # 42 24

Decorators: functions that wrap functions

A decorator takes a function and returns a new function that adds behaviour around it: timing, logging, caching, retrying. @decorator above a definition is shorthand for f = decorator(f).

import time, functools, random

def timed(fn):
    @functools.wraps(fn)                       # keep the original name and docstring
    def wrapper(*args, **kwargs):
        t0 = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:
            print(f"{fn.__name__} took {time.perf_counter() - t0:.3f}s")
    return wrapper

def retry(times=3, base_delay=0.5):
    """Retry with exponential backoff: the standard pattern for flaky API calls."""
    def deco(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            for attempt in range(times):
                try:
                    return fn(*args, **kwargs)
                except ConnectionError:
                    if attempt == times - 1:
                        raise
                    time.sleep(base_delay * 2 ** attempt + random.random() * 0.1)
        return wrapper
    return deco

@timed
@retry(times=4)
def call_model(prompt):
    ...

You already use decorators: @torch.no_grad(), @dataclass, @property, @app.post("/predict") in FastAPI.

Context managers

with guarantees setup and cleanup, even when an exception is raised: files are closed, locks released, GPU modes restored.

from contextlib import contextmanager

@contextmanager
def timer(label):
    t0 = time.perf_counter()
    yield
    print(label, f"{time.perf_counter() - t0:.3f}s")

with timer("tokenize"):
    words = "a b c".split()
# torch.no_grad(), torch.autocast(...) and open(...) are all context managers

Type hints

Type hints document what a function expects and returns. Python does not enforce them at runtime, but editors and checkers (mypy, pyright) catch whole classes of bugs before you run anything, and frameworks like FastAPI and Pydantic use them to validate data.

from typing import Iterator, Literal, Optional, TypedDict, Callable

def top_k(scores: dict[str, float], k: int = 5) -> list[tuple[str, float]]:
    return sorted(scores.items(), key=lambda kv: kv[1], reverse=True)[:k]

def stream_tokens(text: str) -> Iterator[str]:
    yield from text.split()

class Message(TypedDict):
    role: Literal["system", "user", "assistant"]
    content: str

Metric = Callable[[list[int], list[int]], float]
def evaluate(metric: Metric, preds: list[int], labels: list[int]) -> float:
    return metric(preds, labels)

  1. Write a generator sliding_windows(seq, size) that yields every contiguous window of length size.
    Solution
    def sliding_windows(seq, size):
        for i in range(len(seq) - size + 1):
            yield seq[i:i + size]
  2. Why does the decorator use functools.wraps?
    Solution
    Without it the wrapped function's __name__ and docstring become those of wrapper, which breaks logging, debugging and tools that inspect functions.
