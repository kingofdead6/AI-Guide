SQL you must be able to write

-- Latest row per user (deduplication) with a window function
WITH ranked AS (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY updated_at DESC) AS rn
  FROM profiles
)
SELECT * FROM ranked WHERE rn = 1;

-- 7-day rolling average of daily revenue
SELECT day,
       SUM(amount) AS revenue,
       AVG(SUM(amount)) OVER (ORDER BY day ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS rev_7d
FROM orders GROUP BY day ORDER BY day;

-- Day-1 retention: share of users active the day after signup
SELECT s.signup_day,
       COUNT(DISTINCT a.user_id) * 1.0 / COUNT(DISTINCT s.user_id) AS d1_retention
FROM signups s
LEFT JOIN activity a ON a.user_id = s.user_id AND a.day = s.signup_day + INTERVAL '1 day'
GROUP BY s.signup_day;

Know: JOIN types (inner, left, full, anti-join via LEFT JOIN … WHERE b.id IS NULL), GROUP BY vs HAVING, window functions (ROW_NUMBER, RANK, LAG, LEAD, running sums), CTEs, and how NULL behaves in comparisons and aggregates.

Pipeline principles

  • Idempotent steps: re-running a job gives the same result. Partition data by date.
  • Point-in-time correctness: a training example must only use features known at that moment. Joining today's features onto last year's labels is leakage. Feature stores exist largely to enforce this.
  • Validate early: schemas, null rates, ranges and distribution checks at ingestion (pandera, Great Expectations).
  • Lineage and versioning: know exactly which data produced which model.
import duckdb, polars as pl
# SQL directly over Parquet files, no database server needed
df = duckdb.sql("""
    SELECT country, COUNT(*) AS n, AVG(price) AS avg_price
    FROM 'data/orders/*.parquet'
    WHERE order_date >= DATE '2025-01-01'
    GROUP BY country ORDER BY n DESC
""").df()

# Polars: lazy, multi-threaded dataframe
out = (pl.scan_parquet("data/orders/*.parquet")
         .filter(pl.col("price") > 0)
         .group_by("user_id").agg(pl.col("price").sum().alias("spend"))
         .collect())
