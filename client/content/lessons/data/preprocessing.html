Scaling

$$\text{standardize: }z=\frac{x-\mu}{\sigma},\qquad\text{min–max: }x'=\frac{x-x_{\min}}{x_{\max}-x_{\min}}$$

Scaling matters for anything using distances or gradients (kNN, SVM, linear models, neural nets) because unscaled features make the loss surface ill-conditioned ([[optimization]]). Tree models don't care.

Encoding categoricals

  • One-hot: one binary column per category; good for low cardinality.
  • Ordinal: integers for ordered categories (small < medium < large).
  • Target encoding: replace each category by the mean target; powerful for high cardinality but must be computed out-of-fold to avoid leakage.
  • Embeddings: learned vectors per category inside a neural network.

Other transformations

Impute missing values (median, mode, or model-based) and add a "was missing" indicator. Log-transform right-skewed values like prices and counts. Clip or winsorize extreme outliers (IQR rule: outside \([Q_1-1.5\,\text{IQR},\,Q_3+1.5\,\text{IQR}]\)). Extract date parts, ratios, aggregates and domain features.

Splits and leakage

  • Train / validation / test, e.g. 70/15/15. Tune on validation; touch test once at the end.
  • Stratify classification splits to preserve class ratios. For time series, split by time, never randomly. For grouped data (several rows per patient or user), split by group.
  • Fit every transform on training data only, then apply it to validation and test. Pipelines enforce this.

Class imbalance

Use class weights in the loss, resampling (oversample minority, e.g. SMOTE, or undersample majority), threshold tuning, and imbalance-aware metrics (PR-AUC, F1) rather than accuracy.

from sklearn.model_selection import train_test_split
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression

num = ["age", "income"]; cat = ["city", "plan"]
pre = ColumnTransformer([
    ("num", Pipeline([("imp", SimpleImputer(strategy="median", add_indicator=True)),
                      ("sc", StandardScaler())]), num),
    ("cat", Pipeline([("imp", SimpleImputer(strategy="most_frequent")),
                      ("oh", OneHotEncoder(handle_unknown="ignore"))]), cat),
])
model = Pipeline([("pre", pre), ("clf", LogisticRegression(max_iter=1000, class_weight="balanced"))])
X_tr, X_te, y_tr, y_te = train_test_split(df[num + cat], df["y"], test_size=0.2,
                                          stratify=df["y"], random_state=0)
model.fit(X_tr, y_tr)                  # scaler and imputer see training data only
print(model.score(X_te, y_te))
Practice problem
  1. You standardize the whole dataset, then split, then train. Validation accuracy looks great. What went wrong, and how much does it matter?
    Solution
    The mean and standard deviation used test-set information, a mild leak. With standardization the effect is usually small, but the same mistake with target encoding, feature selection or oversampling before splitting can wildly inflate scores. Always split first and fit transforms inside a pipeline.
