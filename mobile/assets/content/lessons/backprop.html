The idea

Represent the computation as a graph. In the forward pass, compute and store each node's value. In the backward pass, go in reverse: each node receives the upstream gradient ∂L/∂output\partial\mathcal L/\partial\text{output}∂L/∂output, multiplies by its local gradient, and passes ∂L/∂input\partial\mathcal L/\partial\text{input}∂L/∂input to its parents. When a value feeds several nodes, its gradients add up.

The pattern repeats for any depth: error signal × input transposed gives the weight gradient; weights transposed × error signal, gated by the activation derivative, gives the next error signal.

NumPy implementation (batched, rows are examples)

rng = np.random.default_rng(0)
# Toy data: 3-class spiral
N, K = 100, 3
X = np.zeros((N*K, 2)); y = np.zeros(N*K, dtype=int)
for k in range(K):
    r = np.linspace(0, 1, N); t = np.linspace(k*4, (k+1)*4, N) + rng.normal(0, 0.2, N)
    X[k*N:(k+1)*N] = np.c_[r*np.sin(t), r*np.cos(t)]; y[k*N:(k+1)*N] = k

H = 100
W1 = rng.normal(0, np.sqrt(2/2), (2, H)); b1 = np.zeros(H)     # He init
W2 = rng.normal(0, np.sqrt(2/H), (H, K)); b2 = np.zeros(K)
lr, lam = 1.0, 1e-3
for step in range(5000):
    # forward
    Z1 = X @ W1 + b1; Hh = np.maximum(0, Z1)
    Z2 = Hh @ W2 + b2
    Z2 -= Z2.max(1, keepdims=True); P = np.exp(Z2); P /= P.sum(1, keepdims=True)
    loss = -np.log(P[np.arange(len(y)), y]).mean() + 0.5*lam*((W1**2).sum() + (W2**2).sum())
    # backward
    D2 = P.copy(); D2[np.arange(len(y)), y] -= 1; D2 /= len(y)    # dL/dZ2
    dW2 = Hh.T @ D2 + lam*W2; db2 = D2.sum(0)
    D1 = (D2 @ W2.T) * (Z1 > 0)                                   # dL/dZ1
    dW1 = X.T @ D1 + lam*W1;  db1 = D1.sum(0)
    for p, g in ((W1, dW1), (b1, db1), (W2, dW2), (b2, db2)):
        p -= lr * g
    if step % 1000 == 0: print(step, round(loss, 4))
print("train accuracy:", ((np.maximum(0, X@W1+b1)@W2+b2).argmax(1) == y).mean())

A tiny autograd engine

This is the core idea of PyTorch in about 30 lines (inspired by Karpathy's micrograd). Each Value remembers its parents and how to push gradients back to them.

import math
class Value:
    def __init__(self, data, parents=()):
        self.data, self.grad, self._parents, self._backward = data, 0.0, parents, lambda: None
    def __add__(self, o):
        o = o if isinstance(o, Value) else Value(o); out = Value(self.data + o.data, (self, o))
        def bw(): self.grad += out.grad; o.grad += out.grad
        out._backward = bw; return out
    def __mul__(self, o):
        o = o if isinstance(o, Value) else Value(o); out = Value(self.data * o.data, (self, o))
        def bw(): self.grad += o.data * out.grad; o.grad += self.data * out.grad
        out._backward = bw; return out
    def tanh(self):
        t = math.tanh(self.data); out = Value(t, (self,))
        def bw(): self.grad += (1 - t*t) * out.grad
        out._backward = bw; return out
    def backward(self):
        order, seen = [], set()
        def topo(v):
            if v not in seen:
                seen.add(v); [topo(p) for p in v._parents]; order.append(v)
        topo(self); self.grad = 1.0
        for v in reversed(order): v._backward()

a, b = Value(2.0), Value(-3.0)
c = (a * b + a).tanh(); c.backward()
print(a.grad, b.grad)      # gradients via the chain rule
Why reverse mode?

We have millions of inputs (parameters) and one output (the loss). Reverse-mode differentiation gets all the partial derivatives of one output in a single backward pass, roughly two to three times the cost of the forward pass. Forward mode would need one pass per parameter.
