The planning problem

Find a path from a start to a goal configuration that avoids collisions, then turn it into a trajectory (positions over time) the controller can follow. The space of all robot configurations is the configuration space (C-space): two joint angles for the arm in Rigid-Body Motion & Kinematics, (x,y,θ)(x,y,\theta)(x,y,θ) for a car. Obstacles in the world become forbidden regions of C-space.

Graph search: Dijkstra and A*

Discretize the space into a grid or graph, then search. Dijkstra expands nodes in order of cost-so-far g(n)g(n)g(n) and finds the shortest path. A* expands in order of

f(n)=g(n)+h(n)f(n)=g(n)+h(n)f(n)=g(n)+h(n)

where h(n)h(n)h(n) is a heuristic estimate of the remaining cost. If hhh is admissible (never overestimates, like straight-line distance), A* still returns the optimal path while exploring far fewer nodes. With h=0h=0h=0 it reduces to Dijkstra; with a weighted heuristic w hw\,hwh, w>1w\gt1w>1, it trades optimality for speed.

import heapq

def astar(grid, start, goal):
    """grid[y][x] == 1 means wall. 4-connected moves of cost 1."""
    h = lambda p: abs(p[0] - goal[0]) + abs(p[1] - goal[1])   # Manhattan: admissible here
    frontier = [(h(start), 0, start)]
    came_from, g = {start: None}, {start: 0}
    while frontier:
        _, cost, cur = heapq.heappop(frontier)
        if cur == goal:
            path = []
            while cur is not None:
                path.append(cur); cur = came_from[cur]
            return path[::-1]
        if cost > g[cur]:
            continue                                   # stale queue entry
        x, y = cur
        for nxt in ((x + 1, y), (x - 1, y), (x, y + 1), (x, y - 1)):
            nx, ny = nxt
            if 0 <= ny < len(grid) and 0 <= nx < len(grid[0]) and not grid[ny][nx]:
                new = cost + 1
                if new < g.get(nxt, float("inf")):
                    g[nxt], came_from[nxt] = new, cur
                    heapq.heappush(frontier, (new + h(nxt), new, nxt))
    return None                                        # no path

Grids explode in high dimensions: a 7-joint arm discretized at 100 values per joint has 101410^{14}1014 cells.

Sampling-based planning: PRM and RRT

  • Probabilistic roadmap (PRM): sample random collision-free configurations, connect nearby ones with collision-free straight segments, then run A* on the resulting graph. Good when you plan many queries in the same environment.
  • Rapidly-exploring random tree (RRT): grow a tree from the start: sample a random point, find the nearest tree node, step a short distance toward the sample, keep the new node if the step is collision-free. The tree is pulled toward unexplored space and quickly finds a path even in high dimensions.
  • RRT* also rewires nearby nodes when a cheaper parent exists, so the path converges toward optimal as samples grow.

Sampling planners are probabilistically complete: if a path exists, the probability of finding it approaches 1 as samples increase. Their raw paths are jagged, so they are shortcut and smoothed afterwards.

From path to trajectory

A path is geometry; a trajectory adds timing that respects velocity, acceleration and jerk limits. Common tools: polynomial or spline interpolation through waypoints (cubic and quintic polynomials give smooth position, velocity and acceleration), time-optimal parameterization along a fixed path, and trajectory optimization, which directly minimizes a cost such as

Planning for autonomous vehicles

Driving stacks usually layer planners: a route planner (graph search on the road network), a behaviour planner (lane change, yield, stop), and a local motion planner that generates and scores candidate trajectories every 50–100 ms against predicted motion of other agents. Learned components increasingly predict other agents' behaviour or propose trajectories, with classical checks for safety.

Practice problems
  1. On a 4-connected grid, is Euclidean distance an admissible heuristic? Is it as good as Manhattan distance?
    Solution
    It is admissible (straight-line distance never exceeds the grid path length) but weaker: Manhattan distance is also admissible and larger, hence closer to the true cost, so A* expands fewer nodes with it.
  2. Why do planners for 7-joint arms use RRT rather than a grid?
    Solution
    A grid grows exponentially with dimension (k7k^7k7 cells), while RRT only samples where it explores and checks collisions along short segments, so it scales to high-dimensional configuration spaces.
