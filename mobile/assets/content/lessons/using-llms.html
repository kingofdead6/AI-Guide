Prompting that works

  • Be explicit about the task, audience, constraints and output format. Give context the model can't guess.
  • Show a few examples (few-shot), including tricky edge cases.
  • Ask for reasoning before the final answer on hard problems, or use a reasoning-capable model.
  • Separate instructions from data with clear delimiters (e.g. XML-style tags), and treat retrieved or user-supplied text as data, never as instructions, to resist prompt injection.
  • Request structured output (JSON matching a schema) and validate it in code.

Evaluation is the real work

  1. Build a test set of realistic inputs with expected outputs or grading criteria (start with 50–200).
  2. Score with exact checks where possible (string match, unit tests, schema validation).
  3. Use LLM-as-judge with a clear rubric for open-ended outputs, and spot-check the judge against human ratings; judges have biases (length, position, self-preference).
  4. Re-run the suite on every prompt or model change. Track cost and latency alongside quality.

SCHEMA_HINT = '{"sentiment": "positive|negative|neutral", "confidence": 0-1, "reason": str}'
def classify(review: str) -> dict:
    prompt = (f"Classify the sentiment of the review inside <review> tags.\n"
              f"Return only JSON in this shape: {SCHEMA_HINT}\n"
              f"<review>{review}</review>")
    for _ in range(3):                                  # retry on malformed output
        try:
            out = json.loads(llm(prompt))
            assert out["sentiment"] in {"positive", "negative", "neutral"}
            return out
        except (json.JSONDecodeError, KeyError, AssertionError):
            continue
    raise ValueError("model did not return valid JSON")

def evaluate(cases):                                    # cases: [(text, expected_label)]
    hits = sum(classify(t)["sentiment"] == y for t, y in cases)
    return hits / len(cases)
