Habits that pay off

  • Type hints, a formatter and linter (ruff), and pre-commit hooks.
  • Config objects (dataclasses, YAML, Hydra) and a CLI (argparse/typer) so every run is reproducible from a command.
  • Logging instead of print; log the git commit, config and data version with each run.
  • Small pull requests with clear descriptions; review others' code.
  • Version large data and models outside git (DVC, object storage, model registry).

Testing ML code

Unit-test data transforms on tiny hand-made inputs. Test output shapes and dtypes. Test that the model can overfit a single batch. Test invariances (a flipped image should keep the same label) and directional expectations (more square metres should not lower a predicted price). Fix seeds for determinism in tests.

# tests/test_model.py  (run with: pytest -q)
import torch
from my_project.model import MLP

def test_output_shape():
    m = MLP(10, 32, 3)
    assert m(torch.randn(4, 10)).shape == (4, 3)

def test_can_overfit_one_batch():
    torch.manual_seed(0)
    m = MLP(10, 64, 3); x = torch.randn(16, 10); y = torch.randint(0, 3, (16,))
    opt = torch.optim.Adam(m.parameters(), 1e-2)
    for _ in range(300):
        loss = torch.nn.functional.cross_entropy(m(x), y)
        opt.zero_grad(); loss.backward(); opt.step()
    assert loss.item() < 0.05

Performance and the machine

Profile before optimizing (cProfile, py-spy, torch.profiler). The usual training bottleneck is the data loader: use more workers, pinned memory, pre-processed Parquet or sharded datasets. Be at home on Linux: ssh, tmux, nvidia-smi, htop, environment variables, and Docker for reproducible environments.
