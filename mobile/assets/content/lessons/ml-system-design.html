A framework for any design question

  1. Clarify the goal and constraints: business objective, users, scale (QPS, number of items), latency budget, freshness, privacy, cost.
  2. Frame the ML task: what exactly is predicted (classification, ranking, generation), at what granularity, and how it drives the product.
  3. Metrics: offline (AUC, NDCG, recall@k, faithfulness) and online (CTR, retention, revenue, resolution rate), plus guardrails (latency, complaints, fairness).
  4. Data and labels: sources, how labels are obtained (explicit, implicit, human, LLM), delays, biases, leakage risks.
  5. Features and representations: user, item, context, cross features, embeddings; online vs batch computation; feature store.
  6. Model: start with a simple baseline, then the stronger model; justify each step up in complexity.
  7. Serving: batch vs online, multi-stage funnels, caching, ANN indexes, hardware, latency breakdown.
  8. Evaluation and launch: offline evaluation, shadow mode, A/B test, ramp-up.
  9. Monitoring and iteration: data and prediction drift, retraining cadence, feedback loops, failure handling.

Back-of-the-envelope numbers

100M daily users × 20 requests ≈ 2B requests/day ≈ 23k QPS on average (plan for 2–3× peak). 100M items × 256-dim fp32 embeddings ≈ 100 GB. A ranking model budget of 50 ms for 500 candidates means 0.1 ms per candidate or batched GPU inference. Doing this arithmetic out loud shows seniority.

What interviewers listen for

Asking clarifying questions before designing; a working baseline before the fancy model; explicit trade-offs (latency vs quality, freshness vs cost); awareness of data problems (leakage, bias, feedback loops); and a plan to measure success after launch.
